# Anonymizer MCP with LM Studio (basic workflow)

Selector-only inventory addressing for MedGemma in LM Studio. Curated project
data is never accessed via filesystem paths from the chat client.

## Start the MCP server

Streamable HTTP (typical with LM Studio `mcp.json` URL):

```bash
cd /path/to/anonymizer
uv sync --extra mcp
uv run rsna-anonymizer --mcp --transport streamable-http --host 127.0.0.1 --port 8000
```

Or stdio (LM Studio spawns the process):

```bash
uv run rsna-anonymizer --mcp
```

Point LM Studio at this server. Load **medgemma-4b-it** (or MLX variant).

## What the LLM receives (MCP protocol)

Per the [MCP tools spec](https://modelcontextprotocol.io/specification/2025-11-25/server/tools):

1. **`initialize`** → `instructions` from `mcp/assets/instructions.md`
2. **`tools/list`** → each tool’s `name`, `description`, and `inputSchema` (JSON Schema),
   generated by the MCP Python SDK from registered tool functions
   (`Annotated` + `pydantic.Field` in `mcp/tools/__init__.py`)

Both payloads are logged in full on the `anonymizer.mcp` logger when returned to the client.

## Addressing rules

- Call **`list_inventory`** for the series table (not `project_info`).
- Rows include `patient_index`, `study_index`, `series_index`, `row_index`,
  `anon_patient_id`, modality, descriptions, `pixel_phi_scanned`.
- **No** `series_path` / disk paths in inventory or imaging tool results.
- Target series with selectors only, e.g. `patient="1"`, `series="latest"`,
  or `series="all"` for every series.

## Suggested prompts (phase 1 — no image display)

1. Create new anonymizer project MCP_MVP
2. Import the files in directory: `/path/to/your/DICOM/folder`
3. List the project inventory
4. Remove all burnt-in annotations from all images in the project
5. List the project inventory again (confirm `pixel_phi_scanned`)

Expected tools: `create_project` → `import_directory` → `list_inventory` →
`remove_pixel_phi` with `series="all"` → `harmonize_studies` → `list_inventory`.
